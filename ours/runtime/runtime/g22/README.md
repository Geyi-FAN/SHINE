# G2.2：关闭状态对照、未松手恢复与独立语音预检

这是独立集成工作树，基础提交为 `ae0777b`。没有替换生产8787，没有改模型参数、YOLO权重、v2.5数值评分或119份冻结F28d文件。

## 运行实现

| 文件 | 作用 |
|---|---|
| `context.py` | 试验开始前恢复完整状态；在控制器初始化之后补回接触求解器缓存。运行期间禁止恢复状态 |
| `return_release.py` | 对停滞的归位阶段补充观察触发；Agent请求释放，原保护器验证并执行；不生成下一阶段答案 |
| `native_wait.py` | Native每次新动作请求将异步等待目标绑定到请求时的手位，避免拉回episode初始手位 |
| `gateway.py` | 独立语音网关；复用单一物理出口、当前任务验收与episode记忆，支持真正停止物理时间的暂停 |
| `run_audio.py`、`audio_smoke.mjs` | 隔离服务与真实PCM语音客户端；不注入转写、不重启现有网页 |

## 诊断实现

- `schedule_close.py`／`close_pair.py`：4个保存的完整关闭进入状态，各比较原调度与几何预检。固定原Agent已选的阶段、完整Task、种子和输入图像；每次400控制步。这是阶段诊断，不是自主完整任务成功率。两个C4状态来自同一配置的两条历史轨迹，不是4个独立任务。
- `make_release_fixture.py`：从历史最后的机器人与物体姿态重建未松手状态，速度清零、12步稳定后保存完整快照。不是原轨迹的精确续接，不能冒充历史失败逐位复现。
- `release_stage.py`：同快照的固定归位阶段对照。第二版保留原归位阶段已执行1196步的年龄，两组先取得相同12控制步新观测，预算300步。恢复只由当前图像/YOLO/本体状态和历史目标触发。
- `run_release.py`：从重建状态重新进入完整Agent规划的额外诊断；两组均可成功，未证明新增恢复提高完整任务成功率。
- `run_natural_return.py`：原酒瓶卡住案例的实际自然源任务回归，不在切换时reset/预暂停，保留首次结果；与旧版源任务实际切换快照不保证完全相同。
- `offline_release_review.py`：对真实历史悬空/遮挡图像进行新Agent复核，不执行动作。

## 释放的保护条件

1. 当前确实是归位阶段，已执行至少180控制步，最多增加2轮复核，沿用原总观察次数上限。
2. 4个新观测跨至少8控制步；当前K2与episode-start K2距离不超过原6像素阈值；点稳定、手停滞且夹爪闭合、目标在手附近。这里只允许请求观察，不代表归位完成。
3. 观察Agent依据当前MAIN、WRIST确认实际支撑，主动请求 `release_supported_in_place`。两次独立新帧请求必须相隔至少8步、对象相同、有可见支撑，且当前机器人/目标保护条件仍满足。
4. 仅保持当前手位并打开夹爪16步。此操作不写入完成事件。
5. 后续撤离也需要Agent请求及当前开手/支撑条件；仍由原观测阶段验收器确认归位，独立v2.5评分器判断完整任务。

悬空、未知支撑、失去当前点、正在搬运、已换持另一对象等情况不能靠历史点自动松手；从不读取物体GT来触发工具。

## 语音预检边界

使用已人工试听通过的英文TTS四轮：放碗到炉灶→暂停并持有→继续→改放盘子。原任务真实执行到持碗状态后设置受控观察窗口；该触发使用私有仿真状态，只用于安排音频，不发送给Agent。它不是“不预先控制动作”的自然打断成绩。

暂停时禁止所有 `env.step`；对比物理步、仿真时间和状态哈希。恢复须收到真实工具回执，解除受控观察窗口并执行新的原任务动作，再发改目标音频。新任务重新绑定完整验收，保留episode历史，仅更新接管记忆。

语音、ASR和TTS经过原实时语音服务；四个执行角色仍是本地模型。输出音频用按真实时钟接收的PCM保存，未使用物理扬声器，也未验证真人麦克风/噪声。

私有端口18981/18987/18989仅绑定127.0.0.1。客户端结束后仅关闭本轮子进程。配置和凭据不在版本控制中。

真实接入修复还包括：`completion_race.py`只对同录音/同任务/同语义版本、仅一次自动完成造成的版本变动重新核验；新任务重新绑定私有完整验收；Native目标触达仅进入保持候选，最终回执由当前完整验收统一产生；动作回执保留原内核需要的审计字段。最后一版客户端等待新终态音频完整接收回执后结束，避免只看到文字就写成播报通过。
