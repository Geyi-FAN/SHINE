# 372例停止的修复：按证据识别客户端截止时未返回的Agent请求

日期：2026-11-15，北京时间。对象为原同一1770注册队列；372份旧首试结果保留，不修改原Ours930成绩。

## 原因

前一版自动恢复已实际成功三次，最终在`B1:T3:T3S50_EM_S03_I00:R01`停止。该例初始音频完整接收、波形和发送时序校验通过，独立评分也完成；客户端等待`source_acceptance`超过原时限，结束时Agent仍在planning，已有请求文件却没有响应/transport结束记录，收尾接口返回owner_not_responding。

这是“请求未完成、客户端先到截止时间”的情况；不能确定一定是云服务内部故障，也可能涉及请求等待。此前分类器仅覆盖T5，漏掉T3，因此按未知异常保护性停止。不是372例都失败，也没有显存不足或训练权重损坏证据。

## 修复

不再按T3/T5分支名称判断，而检查以下证据是否全部成立：

1. 客户端已结束，确实记录到截止时间错误。
2. 输入音频确实发送且质量校验通过。
3. 独立评分正常结束。
4. 最后Agent状态仍为planning，且没有正常ENGINE_FINISHED记录。
5. 有Agent请求文件，但尚无对应response及transport结束记录。

符合这些条件，保留该例失败结果，收尾后独立检查网络，再继续未开始项。不满足这些证据、已有响应却解析异常、输入/评分损坏、事实时间不对齐、账户拒绝等情况仍停止复核。

保留之前的端口复用修复；模型内正式请求不重发，不增加原案例的规划、动作或播报时限，不补写成功回执。
