进度停止时，不继续展示过期的确定完成时刻；恢复后重新估算。

## 可以自动做什么

- 原调度器临时网络检查失败退出后，等待健康恢复；或调度进程意外退出且没有半途案例时，使用原v3文件的完全一致副本恢复运行。
- 必须先核对源文件、原注册表、原372结果及所有监测器首次见到的已发布结果哈希；所有历史故障均需被原分类器识别。
- 有运行锁或存活调度器时绝不另开；有开始但未形成结果的案例时绝不重放。
- 仅在没有在途案例、没有调度进程时，通过该版本自己的STOP_SERVICES清理其遗留模型服务，不操作其他项目。
- 自动重新准入前独立验证原云模型/接口；最多每5分钟检查一次，12小时最多3次完整进程重新启动，避免反复启动耗费资源。
- 新版本目录、APPROVED.json、RETAINED_SHA.json和CONTROL.json保存每次接续身份。正式失败不改分、不覆盖；已结束案例不再执行。

## 不能自动做什么

**它不是无人值守的任意代码修复Agent。**未知代码缺陷、模型身份改变、评分/参考事实异常、损坏音频、账户拒绝、结果哈希变化或半途案例会留诊断并要求处理，不会自行编写补丁、改权重或放宽计分。未知问题仍需实际排查，不能承诺自动修复任何新错误。

超过5分钟没有新增结束项只先提示检查，不自动将较长的合法任务判为死锁。账号权限/余额问题不能靠脚本充值或更换密钥解决。

## 判分保护

本地finalizer_guard观察已有进程，不重复启动。若采集因故提前退出导致原等待进程结束，只在完整1770项齐全、尚未开始准备/模型判分时恢复原finalizer。出现部分语义判分后不从头重判，也不选择更好的答案；此类异常单列处理。模型输出错误和独立评分错误都不能被监测器改成成功。
